One-time setup needed

This page stores its data in a free Firebase Realtime Database so the whole guild sees the same survey results. Before it'll work, someone needs to connect it to a Firebase project (five minutes, no coding):

  1. Go to console.firebase.google.com and create a free project.
  2. In the project, open Build → Realtime Database and click Create Database (any region is fine). Start it in test mode for now.
  3. Go to Project settings (gear icon) → scroll to Your apps → click the </> (Web) icon → register an app (any nickname) → copy the firebaseConfig object it shows you.
  4. Open this HTML file in a text editor, find the FIREBASE_CONFIG block near the top of the <script> section, and paste your config in, replacing the placeholder values.
  5. Save the file and re-upload it wherever you're hosting it (e.g. push to GitHub Pages). Reload this page.

Security note: test-mode rules leave the database open to anyone who has the URL to your Firebase project. That's fine while setting things up, but once things are working, tighten your rules under Build → Realtime Database → Rules — see the included README for the rule set this page expects.

Discord login setup needed

Voting on the WoW Forever survey requires logging in with Discord. Someone needs to connect this page to a Discord application first (five minutes, no coding):

  1. Go to the Discord Developer Portal and click New Application.
  2. Open the OAuth2 tab. Under Client information, toggle Public Client ON and save — this lets the login work with no server and no secret key.
  3. Still on the OAuth2 tab, under Redirects, add this page's exact URL: …
  4. Copy the Client ID from the top of the OAuth2 page.
  5. Open this HTML file in a text editor, find the DISCORD_CONFIG block near the top of the <script> section, and paste your Client ID in, replacing the placeholder.
  6. Save the file, re-upload it, and reload this page. The first person who logs in becomes Admin.

This value isn't secret the way a client secret would be — Discord's "Public Client" mode is specifically designed to work safely from a plain web page like this one.

One more step: lock down the database

Discord login alone only gates the voting UI — it doesn't stop someone from reading your Firebase database directly. A small, free Cloudflare Worker closes that gap by verifying each login and issuing a real Firebase sign-in token. Full step-by-step instructions (with the Worker code to paste in) are in the included README.md. Short version:

  1. Generate a Firebase service account key (Project settings → Service accounts).
  2. Create a free Cloudflare account, deploy the provided Worker code, and set that key as an encrypted secret.
  3. Copy the Worker's URL into the WORKER_URL constant near the top of this file's <script> section (append /mint-token).
  4. Update your Firebase Realtime Database rules to the version shown in the README.

Until this is done, your database is still readable/writable by anyone who finds its URL, regardless of the Discord login.
